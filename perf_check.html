HQAA 포털 속도 진단

느림이 내 PC/브라우저·정적 파일·Apps Script 요청 경로·Apps Script 내부 처리 중 어디에서 발생하는지 구간을 나눠 측정합니다. 측정 중에는 다른 탭 작업을 멈춰주세요. (약 40~80초 소요)
이름/사번을 넣으면 로그인이 필요한 항목(팀회의 요약, 내 식수 상태)까지 측정합니다. 포털에 이미 로그인한 상태면 자동으로 채워집니다. 비워도 핵심 진단은 가능합니다.

진단 결과

1. 내 PC / 브라우저 성능 (서버와 무관)

2. Apps Script 기본 왕복 시간 기준선

시트·Drive·캐시를 전혀 열지 않는 전용 진단 요청(action=perfPing)으로 요청 경로 + Apps Script 실행 시작 비용만 측정합니다. 여기서 이미 느리거나 편차가 크면 시트 데이터와 무관한 구간의 문제입니다.

3. 홈 화면 실제 로딩 실제 호출 방식

현재 포털 홈은 getHomeBundle 1회 호출로 공지·식수·회의실·팀회의를 한 번에 받습니다. 이 항목은 그 방식 그대로 반복 측정합니다.

요약

서버 내부 처리 분해 (진단 모드 응답)

네트워크·실행대기 = 브라우저 왕복 − 서버 내부 처리시간. 이 값이 크면 시트 처리가 아니라 요청 진입/실행 시작 구간이 오래 걸린 것입니다.

4. 개별 API 진단 실제 홈 호출 방식 아님

홈 화면은 이 API들을 개별 호출하지 않습니다(3번 항목이 실제 방식입니다). 아래는 병목이 어느 데이터에서 발생하는지 위치를 좁히기 위한 개별 진단입니다.
순수 시트비용 = 응답시간 − 기본 왕복 최소시간(참고값). 기준선이 불안정하면 대기시간이 시트 비용으로 잘못 계산되므로 이 열은 표시하지 않습니다.
